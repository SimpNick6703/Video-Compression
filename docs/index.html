How the PCIe numbers are calculated

One raw frame in NV12 / YUV420p takes width × height × 1.5 bytes.

  • 1080p: 1920 × 1080 × 1.5 = 3,110,400 B/frame (3.11 MB) × 14,216 = 44.22 GB (186.6 MB/s at playback speed)
  • 720p: 1280 × 720 × 1.5 = 1,382,400 B/frame (1.38 MB) × 14,216 = 19.65 GB (82.9 MB/s at playback speed)

Native 1080p: frames never leave VRAM. Only the compressed bitstream crosses PCIe: 457 MB in + 88 MB out ≈ 545 MB.

Downscaled to 720p (legacy hybrid): FFmpeg downloads every decoded 1080p frame to system RAM for CPU Lanczos scaling (44.22 GB device → host), then uploads the 720p frames back to NVENC (19.65 GB host → device). With the bitstream that is ≈ 64.41 GB of PCIe traffic.

Hardware Native Unscaled (1080p60)

Zero-copy VRAM execution with zero software scaling copies.

Frames are demuxed from storage and streamed as compressed NAL packets across PCIe into GPU VRAM. NVDEC decodes into CUDA surfaces, the frame scaling filter is completely bypassed (zero software pixel copies), and NVENC encodes directly on-chip. Only compressed bitstream traverses PCIe.

Why it matters: When the BPP calculator decides to downscale (for example 1080p to 720p), running the scaler on the CPU forces a ~64 GB PCIe roundtrip. The zero-copy pipeline resizes frames in video memory with each vendor's native scaler instead: scale_cuda on NVIDIA, scale_vaapi on VA-API, vpp_amf on AMD, vpp_qsv on Intel and scale_vt on macOS. The NVIDIA case measured here gets back to native 545 MB PCIe traffic without losing quality. If an input cannot be decoded in hardware, the pipeline falls back to an upload tier, then to the legacy path.

5 · Split & stitch

How one video becomes two parallel encodes

Hardware encodes run as two workers at once. The split point is found by reading packet headers only, so no video is decoded to choose it.

  1. Step 1 · Probe

    Read packet headers

    ffprobe -select_streams v:0
  -show_entries packet=pts_time,size,flags
  -of csv=p=0

    A line-by-line reader adds up packet sizes and notes keyframe timestamps (flags=K). No frames are decoded and memory stays under 10 MB.

  2. Step 2 · Balance

    Split at 50% of the bytes

    The split point T is the keyframe closest to half of the total byte weight, so both workers get an equal amount of data. Cutting on a keyframe means each half can be decoded on its own.

  3. Step 3 · Encode

    Two workers in parallel

    Worker 1 encodes 0 → T, worker 2 encodes T → end, each as its own FFmpeg process with a bitrate for its half. Worker 2 resets its timestamps to zero with -avoid_negative_ts make_zero.

  4. Step 4 · Stitch

    Join without re-encoding

    ffmpeg -f concat -safe 0 -i list.txt -i input
  -map 0:v:0 -map 1:a:0? -c:v copy -c:a copy
  -movflags +faststart

    Both halves are encoded without audio. FFmpeg joins the video halves without re-encoding, takes the audio from the source in one piece (copied, or re-encoded to AAC when the audio rule says so), and moves the index (moov box) to the front of the file so it can start playing before it fully downloads.

Background · Decisions · Measurements

HDR, Color Depth and Codecs

These three properties of a video decide whether it can stay HDR, whether it can stay on the GPU, and how long compressing it takes. They are often mixed up, but each answers a different question.

Codec
How is it packed?
H.264, HEVC, AV1: the method that compresses the frames
Color depth
How fine are the steps?
8-bit or 10-bit: how many shades each channel can store
Dynamic range
What do they mean?
SDR or HDR: how bright and how saturated each value is

1 · Codec

The method that compresses the frames

A codec turns raw frames into a bitstream and back. It is not the file type: .mp4, .mkv and .mov are containers, and each can hold several codecs. Newer codecs need fewer bits for the same quality, but fewer devices can play or encode them.

Codec Bitrate for similar quality Plays on 10-bit GPU encoding In Video-Compression
H.264 (AVC) Baseline (100%) Almost everything Rare, and 10-bit H.264 rarely plays Output for compatibility, always SDR when the source is HDR
HEVC (H.265) Roughly 50–70% Most devices from recent years Common (Main 10) Default output, can keep HDR
AV1 Roughly 40–60% Newer devices only Only on the newest GPUs Input only

Why it matters here: At a fixed file size, a more efficient codec means better quality. That is why HEVC is the default. AV1 is not offered as an output because too few GPUs can encode it and too few devices can play it.

2 · Color depth

How many steps exist between black and white

More bits do not make a video brighter or more colorful. They make the steps between neighboring shades smaller, so smooth skies and glows do not break into visible bands.

8-bit 256 levels · 16.7 million colors

A raw 4K frame takes 12.4 MB (NV12).

10-bit 1,024 levels · 1.07 billion colors

A raw 4K frame takes 24.9 MB (P010).

The bands are exaggerated (12 steps against 48, the same 1:4 ratio) so the difference shows on any screen.

Why it matters here: Converting 8-bit to 10-bit cannot bring back shades that were never recorded. The output therefore matches the source: 10-bit HDR stays 10-bit, and 8-bit HDR stays 8-bit.

3 · Dynamic range

What the stored numbers mean

A pixel only stores numbers. Color tags tell the player how to turn them into light. The transfer function maps a number to brightness, and the primaries say which red, green and blue are meant. Read HDR numbers as SDR and the picture looks gray and washed out.

Property SDRBT.709 HDR10PQ HLGHybrid Log-Gamma
Brightness Mastered for about 100 nits Absolute, up to 10,000 nits Relative to the display, typically 1,000 nits
Color gamut BT.709 BT.2020 BT.2020
Usual color depth 8-bit 10-bit 10-bit
Often comes from Screen recordings, the web Game capture, films Phones, cameras, broadcast
Transfer tag the app reads bt709 or none smpte2084 arib-std-b67

HDR is not the same as 10-bit: 10-bit SDR and 8-bit HDR both exist. HDR is usually 10-bit because spreading 8 bits over such a wide range shows banding, but it is the transfer tag that makes a video HDR.

The app reads the transfer tag (from the first frame, or from the container if the frame has none) and the pixel format, then combines them with the output codec and the encoder that is available.

5 · Tone mapping

How HDR becomes SDR

Tone mapping squeezes a very wide brightness range into SDR while keeping detail in the highlights. It works on every pixel of every frame in floating point, after any downscale so that there are fewer pixels to process.

  1. Step 1 · Linearize

    Numbers to light

    zscale=t=linear:npl=100
format=gbrpf32le

    Undo the HDR transfer so the math works on real light, with 1.0 meaning 100 nits.

  2. Step 2 · Gamut

    BT.2020 to BT.709

    zscale=p=bt709

    Express each color with the narrower SDR primaries. Without this step colors look faded.

  3. Step 3 · Compress range

    Hable curve

    tonemap=hable:desat=0

    Roll off highlights smoothly instead of clipping them to flat white.

  4. Step 4 · Re-encode

    Light to SDR numbers

    zscale=t=bt709:m=bt709:r=tv

    Apply the SDR curve, tag the result BT.709 and hand it to the encoder.

Two adjustments to step 1: HLG adds agamma=0, because zscale's faster default applies HLG's system gamma to each channel separately and shifts saturated colors. The exact math makes HLG conversion 1.3–1.5 times slower at 4K60, and HDR10 does not need it. When the frames lack color tags, the transfer comes from the container and BT.2020 is assumed for primaries and matrix, as both HDR formats specify. Dolby Vision profile 5 carries no HDR transfer tag, so it is not recognized as HDR.

Why tone mapping runs on the CPU

FFmpeg has no CUDA tone-mapping filter, so there is no equivalent of scale_cuda for this step. These alternatives were prototyped with plain FFmpeg on an RTX 4060 laptop (video only, one encode at a time):

Method, 8.5 s 4K60 HDR10 Time CPU Catch
zscale and tonemap (shipped) 26.1 s 72% Uses the CPU, works on every platform
libplacebo on Vulkan 8.3 s 7% Adds a Vulkan renderer and shader compiler to every build, still needs a CPU fallback, and zero-copy from CUDA failed
tonemap_opencl 7.7 s 14% Brighter, warmer picture and the wrong output range

tonemap_vaapi was also tried on an Intel iGPU. It refuses videos without mastering display metadata, which game recordings often lack.

Only HDR sources saved as H.264, or encoded without a GPU, need this step. That is too narrow a gain for the extra size and upkeep, so it stays on the CPU.

Parallel Processing Engine

By dividing the video at a calculated keyframe and utilizing Python's threading to run multiple FFmpeg subprocesses simultaneously, the tool significantly reduces encoding times on hardware encoders. CPU encoders run as one process.

Progress Aggregation

A thread-safe ProgressTracker class parses stderr from both FFmpeg instances, merging ETA and speed metrics into a unified console output.

Parallel Split Encoding

Hardware encoders execute a dual-worker parallel split pipeline with on-chip rate control, plus lookahead or pre-analysis on NVENC, AMF and QSV.

Safe Concatenation

Chunks are stitched using FFmpeg's concat demuxer with +faststart, relocating the moov atom to the front for progressive streaming without re-encoding.

Exceptions and how this was tested

Pipeline names: when decoding, scaling and encoding all run on the GPU the app calls it zero-copy. CPU decoding followed by GPU work is upload. On NVENC without scaling, the app can show zero-copy although the CPU decoded.

Failed GPU pipeline: the app retries once with legacy, which scales on the CPU except on NVENC. It does not switch to a CPU encoder, and HDR to SDR has no retry.

Very wide videos: an encode that stays wider than the GPU encoder supports fails. For most H.264 encoders that is 4,096 pixels, and some older GPUs have a similar limit for HEVC.

10-bit SDR: NVENC keeps 10-bit only for unscaled 4:2:0 HEVC, and VideoToolbox follows the decoded frames. The bundled x265 is 10-bit capable only on Windows.

4:2:2 color: output is 4:2:0, except HEVC on the CPU encoder, which keeps SDR sources in 4:2:2.

HDR detection: only the PQ and HLG transfer tags count. Untagged HDR and Dolby Vision profile 5 are treated as SDR.

Tested: 464 real encodes with the bundled FFmpeg n9.1. They cover 29 inputs (H.264, HEVC, AV1, VP9 and MPEG-4 in SDR, HDR10 and HLG), both output codecs, scaled and unscaled, on NVENC (RTX 4060, Windows), VA-API (Intel UHD 630, Linux) and both CPU encoders. AMF, QSV and VideoToolbox rows follow the code and vendor support, and were not run.
